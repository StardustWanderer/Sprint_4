# Sprint 4 — UI Automation Tests (Yandex Scooter)

## О проекте

Учебный проект по автоматизации тестирования веб-приложения **Яндекс Самокат**, выполненный в рамках четвёртого спринта курса «Инженер по тестированию» (направление автоматизации тестирования на Java) в Яндекс Практикуме.

Цель проекта — автоматизировать проверку отдельных пользовательских сценариев веб-приложения с использованием Selenium WebDriver.

В проекте реализованы UI-автотесты для проверки:
- содержимого выпадающих элементов FAQ на главной странице;
- оформления заказа через различные точки входа;
- отображения модального окна об успешном оформлении заказа.

Для организации кода применён паттерн Page Object Model (POM).

## Задачи проекта

- Изучить принципы автоматизации UI-тестирования с помощью Selenium WebDriver.
- Реализовать Page Object Model для основных страниц приложения.
- Вынести локаторы и методы взаимодействия с элементами интерфейса в отдельные классы.
- Использовать явные ожидания Selenium для синхронизации с веб-приложением.
- Применить параметризацию JUnit 4 для запуска тестов с различными наборами данных.
- Автоматизировать проверку элементов FAQ.
- Автоматизировать пользовательский сценарий оформления заказа.
- Реализовать возможность запуска тестов в разных браузерах.

## Реализованные автотесты

В проекте реализованы два параметризованных тестовых сценария.

### 1. AccordionFaqTest — проверка FAQ

Проверяется корректность отображения ответов на часто задаваемые вопросы на главной странице приложения.

**Сценарий проверки:**
1. Открыть главную страницу Яндекс Самокат.
2. Нажать на заголовок выбранного элемента аккордеона.
3. Получить текст открывшейся панели.
4. Сравнить фактический текст с ожидаемым результатом.

Используется параметризация JUnit 4: тест запускается с восемью наборами данных, каждый из которых соответствует отдельному элементу FAQ.

**Количество запусков:** 8.

### 2. CreateOrderTest — проверка оформления заказа

Проверяется возможность оформить заказ через обе кнопки «Заказать», расположенные в разных частях главной страницы.

**Сценарий проверки:**

1. Открыть главную страницу Яндекс Самокат.
2. Нажать одну из кнопок «Заказать».
3. Заполнить форму с данными пользователя:
    - имя;
    - фамилия;
    - адрес;
    - станция метро;
    - номер телефона.
4. Перейти к следующему этапу оформления заказа.
5. Заполнить параметры аренды:
    - дата доставки;
    - срок аренды;
    - цвет самоката;
    - комментарий для курьера.
6. Нажать кнопку «Заказать».
7. Подтвердить оформление в модальном окне.
8. Проверить отображение финального модального окна «Заказ оформлен».

Используется параметризация JUnit 4 с двумя наборами тестовых данных.

Тест проверяет оформление заказа через верхнюю и нижнюю кнопки на главной странице. Для каждого варианта используются отдельные пользовательские данные и параметры аренды.

Даты доставки формируются динамически относительно текущей даты с помощью `LocalDate` и `DateTimeFormatter`. Это позволяет избежать устаревания тестовых данных.

**Количество запусков:** 2.

## Архитектура проекта

Для организации UI-автотестов используется паттерн **Page Object Model (POM)**.

Локаторы и методы взаимодействия с элементами интерфейса вынесены в отдельные классы страниц. Тестовые классы содержат последовательность пользовательских действий и проверки ожидаемых результатов.

### Пакет `pageobject`

| Класс | Назначение |
|---|---|
| `BasePage` | Базовый класс страниц. Хранит экземпляр WebDriver и WebDriverWait, выполняет ожидание уникального элемента при инициализации страницы. |
| `MainPageScooter` | Работа с главной страницей: кнопки оформления заказа и элементы FAQ. |
| `OrderPageScooter` | Заполнение первой части формы заказа: данные пользователя и выбор станции метро. |
| `RentPageScooter` | Заполнение параметров аренды, работа с кнопками и модальными окнами оформления заказа. |

### Пакет `tests`

| Класс | Назначение |
|---|---|
| `BaseTest` | Базовая настройка тестового окружения: выбор браузера, запуск WebDriver, открытие приложения и закрытие браузера после выполнения теста. |
| `AccordionFaqTest` | Параметризованная проверка текстового содержимого элементов FAQ. |
| `CreateOrderTest` | Параметризованная проверка оформления заказа через две кнопки на главной странице. |

## Особенности реализации

### Page Object Model

Для каждой страницы приложения создан отдельный класс, содержащий:
- локаторы элементов;
- методы взаимодействия с элементами;
- методы для выполнения последовательностей действий пользователя.

Общий функционал вынесен в абстрактный класс `BasePage`, от которого наследуются остальные Page Object.

### Явные ожидания Selenium

Для синхронизации действий тестов с состоянием веб-приложения используются явные ожидания `WebDriverWait` и условия `ExpectedConditions`.

В зависимости от операции применяются ожидания:
- `visibilityOfElementLocated`;
- `presenceOfElementLocated`;
- `elementToBeClickable`.

Это позволяет дождаться появления, видимости или готовности элемента к взаимодействию перед выполнением следующего действия.

### Параметризация JUnit 4

Для проверки нескольких элементов FAQ и различных вариантов оформления заказа используется `@RunWith(Parameterized.class)`.

Тестовые данные передаются через `@Parameterized.Parameters`, а один тестовый метод выполняется с разными наборами параметров.

### Динамическое формирование тестовых дат

В `CreateOrderTest` используется `LocalDate` для получения текущей даты и формирования будущих дат доставки.

`DateTimeFormatter` обеспечивает форматирование даты в соответствии с форматом, используемым полем формы — `dd.MM.yyyy`.

Это позволяет поддерживать актуальность тестовых данных при повторных запусках проекта.

### Переключение браузеров

В `BaseTest` реализован выбор браузера через системное свойство Java `browser`.

По умолчанию используется Firefox. При запуске можно явно указать Chrome или Firefox, не изменяя исходный код.

## Известный дефект приложения в Google Chrome

В тестируемом веб-приложении присутствует известный дефект, который воспроизводится в Google Chrome: после подтверждения заказа в модальном окне не отображается финальное окно «Заказ оформлен».

В связи с этим результаты выполнения тестов различаются в зависимости от браузера:

| Тест | Firefox | Google Chrome |
|---|---|---|
| AccordionFaqTest | PASSED | PASSED |
| CreateOrderTest | PASSED | FAILED — известный дефект приложения |

При запуске `CreateOrderTest` в Chrome проверка завершается с `TimeoutException`, поскольку ожидаемое модальное окно не появляется в установленное время ожидания.

Тестовая реализация сохраняет проверку ожидаемого поведения приложения. Исключение для Chrome не добавляется, а ошибка не подавляется, поскольку это привело бы к сокрытию дефекта тестируемого продукта.

Таким образом, падение `CreateOrderTest` в Chrome связано с известной проблемой приложения, а не с намеренным изменением ожидаемого результата автотеста.

## Запуск проекта

### Требования

- JDK 11.
- Apache Maven.
- Google Chrome и/или Mozilla Firefox.
- IntelliJ IDEA или другая IDE с поддержкой Maven.

### Клонирование репозитория

```bash
git clone <repository-url>
```

Перейти в директорию проекта:

```bash
cd <project-directory>
```

### Запуск тестов в Firefox

Firefox используется по умолчанию:

```bash
mvn clean test
```

Также можно явно указать браузер:

```bash
mvn clean test -Dbrowser=firefox
```

### Запуск тестов в Google Chrome

```bash
mvn clean test -Dbrowser=chrome
```

**Примечание:** при запуске `CreateOrderTest` в Chrome воспроизводится известный дефект приложения. Поэтому неуспешное завершение этого теста ожидаемо и описано в разделе «Известный дефект приложения в Google Chrome».
